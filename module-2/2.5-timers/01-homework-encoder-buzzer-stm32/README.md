# 01 — Homework (extra): an encoder sets the buzzer's tone on the STM32 (Black Pill)

The teacher's extra task for lesson 2.5, on the WeAct Black Pill (STM32F411CEU6). A rotary encoder moves a timer's
counter up and down by itself (TIM4 in encoder mode), and the main loop turns that position into the period of a PWM
signal (TIM3) that drives a passive buzzer, so the knob sets the pitch. An extra the task does not ask for: past the top
of the range (about 3.3 turns up) the buzzer plays "Jingle Bells". Written in C inside the `USER CODE` blocks of
CubeMX's `main.c`. The git history of this folder shows the work one change per commit.

This is a different task from the lesson's main homework (`00-homework-exhaust-fan-esp32`), so it has its own number.

## Assignment

"Extra homework 2_5" (the teacher's message in the group chat, translated in full):

> Using timers, read the change of the encoder's position and change the frequency of the PWM fed to the buzzer
> accordingly.

## How each point is done

| Point | In the code (`Core/Src/main.c`) and the `.ioc` |
|---|---|
| Read the encoder's position with a timer | TIM4 in encoder mode (CubeMX "Encoder Mode TI1", `SMS` = 001 in `TIM4_SMCR`) on PB6 (CH1) and PB7 (CH2). After `HAL_TIM_Encoder_Start()` the timer counts the encoder's edges up or down by itself, with no interrupt and no code in the loop: its counter `CNT` is the knob's position. The loop reads it as `int16_t`, so one count below the start is −1, not 65535 |
| Change the frequency of the PWM fed to the buzzer | TIM3 channel 3 in PWM mode 1 on PB0. The timer ticks at 1 MHz (100 MHz / (PSC 99 + 1)), so the frequency is f = 1 MHz / (ARR + 1). `buzzer_set_arr()` writes ARR = 999 − 5 × position and CCR = (ARR + 1) / 2, so the duty stays at 50 % at every pitch |
| Extra, not asked for: a melody | at position 120 or more (`MELODY_POSITION`), `play_melody()` plays the "Jingle Bells" chorus twice from a table of 51 notes (`static const Note jingle_bells[]`, kept in flash), then the loop reads the knob again |

Position → tone:

| Position (counts) | ARR | Frequency |
|---|---|---|
| −108 | 1539 | 649 Hz |
| 0 (the start after a reset) | 999 | 1000 Hz |
| 119 | 404 | 2469 Hz |
| 120 and more | — | the melody |

The melody sets each note the same way, ARR = 1 MHz / f − 1 (E6, 1319 Hz → ARR 757), holds it with `HAL_Delay()`,
then writes CCR = 0 for a 30 ms gap.

## Project

A CubeIDE project generated by CubeMX into this folder; our code lives only in the `USER CODE` blocks of
`Core/Src/main.c`, which a regenerate keeps.

| Pin | CubeMX setting | Used for |
|---|---|---|
| PB0 | TIM3_CH3, PWM Generation CH3 | the buzzer's signal, through 220 Ω |
| PB6 | TIM4_CH1, Encoder Interface, pull-up | the encoder's `CLK` (A) |
| PB7 | TIM4_CH2, Encoder Interface, pull-up | the encoder's `DT` (B) |
| PA13 / PA14 | SYS: Serial Wire | SWDIO / SWCLK for the ST-Link |
| PH0 / PH1 | RCC: HSE crystal | 25 MHz crystal |

| Timer | Setting | Value |
|---|---|---|
| TIM3 | Prescaler | 99: 1 MHz from the 100 MHz timer clock |
| | Counter Period (ARR) | 999: 1 kHz until the loop writes its own value |
| | Pulse (CCR3) | 500: 50 % |
| | auto-reload preload | on |
| TIM4 | Encoder Mode | TI1 |
| | Counter Period | 65535 (the full 16 bits) |
| | Input filter (IC1, IC2) | 0 |

**Clock:** HSE 25 MHz → PLL (M = 12, N = 96, P = 2) → SYSCLK 100 MHz. TIM3 and TIM4 sit on APB1 (/2 = 50 MHz), whose
timers run at twice that, 100 MHz. STM32Cube FW_F4 V1.28.3, CubeMX 6.18.1, CubeIDE 2.2.0.

Only TIM1 and TIM2–TIM5 have the encoder interface on this chip (RM0383, 12.3.16 and 13.3.12); TIM9–TIM11 don't.

## Wiring

| Part | Connection |
|---|---|
| Buzzer module `S` | 220 Ω → PB0 |
| Buzzer module `−` | GND |
| Buzzer module middle pin | not connected |
| Encoder `CLK` | PB6 |
| Encoder `DT` | PB7 |
| Encoder `+` | 3V3 |
| Encoder `GND` | GND |
| Encoder `SW` (push button) | not connected |
| SWD header | ST-Link V2: 3.3V, SWDIO, SWCLK, GND; the board runs from the ST-Link |

**Why 220 Ω.** The buzzer is a passive electromagnetic one: no oscillator inside, so it sounds at the frequency on its
pin (an active buzzer would beep at its own pitch whatever the PWM). Its coil measured 46.6 Ω with the multimeter.
Straight from a 3.3 V pin that would be 3.3 V / 46.6 Ω ≈ 71 mA, far above the 25 mA limit of one pin (STM32F411CE
datasheet, absolute maximum ratings, I_IO). With 220 Ω in series: 3.3 V / 266.6 Ω ≈ 12 mA. There is no transistor and no flyback diode: the push-pull output always connects the coil to 3.3 V or to GND, so its
current has a path at every edge, and the resistor limits it.

## Notes

- **The encoder is counted in hardware.** TIM4 changes `CNT` on every edge whatever the CPU is doing; the loop only
  reads it. Even while the melody holds the loop for 19 s, no turn is lost.
- **Read the counter as signed.** `CNT` is 16-bit and wraps 0 → 65535 when it counts down. Read as `uint32_t` (the
  version in 72befaf, ARR = 999 + 10 × position), one count down gives 999 + 655350; it still worked, but only by
  luck: the 16-bit ARR register drops the upper bits, and 10 × 65536 is a multiple of 65536, so 989 was left.
  `(int16_t)` reads the same 16 bits as −1.
- **The melody threshold also keeps ARR positive.** 999 − 5 × position reaches −1 at position 200, and as a `uint32_t`
  that is 4294967295. The melody takes over at 120, so the formula never gives less than 404.
- **Preload.** ARR and CCR3 are preloaded (ARPE, and the HAL turns on the channel's output compare preload), so a new
  value starts when the current period ends. The loop can rewrite them on every pass without breaking the wave.
- **Silence is CCR = 0.** In PWM mode 1 the output is high while `CNT` < CCR; with CCR 0 it never is, so PB0 stays low.
  The 30 ms gap after each note keeps repeated notes (E E E) from merging into one long tone.
- **The melody blocks the loop.** `HAL_Delay()` waits; one run takes about 19.2 s. The knob is still counted, but the
  loop looks at it only after the last note, so turning back stops the music only at the end of a run. While the knob
  stays at 120 or more, the melody starts again.
- **No lower limit.** Below −12907 counts (some 360 turns at the measured rate) ARR passes 65535
  (999 + 5 × 12908 = 65539), and the 16-bit register keeps only the low bits: the tone would jump. Not handled.
- **Which way is "up"** depends on the order of the two signals: swapping PB6 and PB7 swaps the directions.
- **No input filter** (ICxF = 0). `CNT` stayed still while the knob was not touched; a filter was not tried.

## Checked on the board

- e598a3a: a steady tone (1 kHz by the registers below; the frequency was not measured). Registers read through the ST-Link (`stm32 reg`): TIM3 `CEN` = 1, `ARPE` = 1,
  ARR = 999, CCR3 = 500, `CC3E` = 1; TIM4 `SMS` = 001; PB6 and PB7 in alternate function mode with pull-ups, both high
  at rest; TIM4's `CNT` unchanged while the knob was left alone.
- 72befaf: the tone follows the knob.
- 459a1c3: about 3 turns in the direction that counts down gave `CNT` = 65428 (−108), ARR = 1539 and CCR3 = 770, as the
  formula says (999 + 108 × 5, then (1539 + 1) / 2), and a lower tone. So about 36 counts per turn (108 in about 3).
- **Not checked on the board:** the melody (120 counts up) and the top of the range.

Build (Debug, `-O0 -g3`): 0 errors, 0 warnings with CubeIDE's flags and with `-Wextra` (`build-stm32.sh`).
`arm-none-eabi-size`: `text` 9712, `data` 12, `bss` 1716 bytes. The note table takes 204 bytes (51 × 4) in `.rodata`,
in flash: `nm` shows `jingle_bells` at `0x08002504`.

## Working with the step

- **Open:** in CubeIDE, File → Open Projects from File System → this folder (opened in place, not copied into the
  workspace).
- **Build:** Project → Build Project (the hammer).
- **Flash:** Run → Run As → STM32 C/C++ Application, with the ST-Link connected. Launch files (`*.launch`) hold
  absolute paths and are not committed, so the first Run creates one.
- **Change pins, timers or the clock** in `01-homework-encoder-buzzer-stm32.ioc` with CubeMX, then regenerate:
  everything in `main.c` outside the `USER CODE` blocks is rewritten.
