## Two boards

The homework is written for the ESP32; a step may also get an STM32 version. Naming and layout rules are in
`../CLAUDE.md` (Repository layout, "Two boards"). What changes between the two:

| | ESP32 (`-esp32`) | STM32 (`-stm32`) |
|---|---|---|
| Board | ESP32-S3 DevKitC-1 clone, N16R8 (root `CLAUDE.md`) | WeAct Black Pill STM32F411CEU6, ST-Link V2 clone (`../module-1/CLAUDE.md`, 1.8) |
| Project | PlatformIO, Arduino core 2.0.17, C++ with `-std=gnu++11` (`platformio-build-esp32s3.py`) | STM32CubeIDE 2.2.0 + CubeMX 6.18.1, HAL FW_F4 V1.28.3, C (`main.c`) |
| Start | the lesson's draft, split into steps by `/save-hw` | generated by CubeMX straight into the step folder |
| Under `loop()` | FreeRTOS: `setup()`/`loop()` run in `loopTask` (8192-byte stack, `cores/esp32/main.cpp`) | nothing: `while (1)` in `main()`, only the SysTick interrupt |
| Time | `millis()`, `micros()` | `HAL_GetTick()` (1 ms SysTick) |
| Pin interrupt | `attachInterrupt()` | the EXTI line set in CubeMX, `HAL_GPIO_EXTI_Callback()` |
| Serial log | `Serial` on the UART port (CH343P) | a UART + the kit's USB-TTL adapter (the ST-Link V2 has no serial port; the board's USB-C is the chip's own USB, which needs a 48 MHz clock) |
| CI | built (`build-all.sh`) | not built (`../module-1/CLAUDE.md`, open 9) |
| Simulation | Wokwi | none |

## What to watch for (common mistakes, including in AI-generated code)

- **`volatile`:** needed for data an ISR writes and `loop()` reads, and for hardware registers. It gives no
  atomicity: a value wider than 32 bits, `counter++` or a read-and-clear can be cut by an interrupt between two
  accesses (see 1.5 in `../module-1/CLAUDE.md`).
- **ISR rules from module 1 still hold:** short, no `delay`, no `Serial`, `attachInterrupt` last in `setup()`
  (`../module-1/CLAUDE.md`, 1.5).
- **Time arithmetic:** `now - last >= interval` with `uint32_t` survives the `millis()` wrap; `now >= last + interval`
  and signed types don't.
- **`constexpr` and memory:** a global `constexpr` table lands in flash (`.rodata`); a local one inside a function
  can be rebuilt on the stack on every call unless it is `static constexpr`. Check with `nm`/`size`, not by belief.
- **Hardware in constructors:** a global object's constructor runs before `setup()`; pin setup belongs in an explicit
  `init()` called from `setup()`.
- **Hidden heap:** Arduino's `String`, `WebServer` and Wi-Fi allocate; the lesson's "no dynamic memory" rule covers
  our code, not the core.
- **Register addresses differ per chip:** an address copied from another MCU's example reads something else.
  STM32F411: `GPIOA` base `0x40020000` is `MODER` (modes); the input levels are `IDR` at offset `0x10` (RM0383 §8.4.5).
