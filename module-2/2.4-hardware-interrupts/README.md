# Lesson 2.4 — Hardware interrupts: reacting to buttons

[← Module 2](../)

**Boards:** ESP32-S3 DevKitC-1 clone (N16R8), ESP-IDF in C (PlatformIO, `framework = espidf`) · WeAct Black Pill
(STM32F411CEU6), STM32CubeIDE, C

A button raises an interrupt the moment its pin changes, so nothing has to keep polling it; the contacts bounce,
though, and one press gives several edges. The homework compares ways to turn those edges into one clean press.

## Steps

| # | Step | Type | What it shows |
|---|---|---|---|
| 00 | homework-button-debounce: [esp32](00-homework-button-debounce-esp32/) · [stm32](00-homework-button-debounce-stm32/) | homework | ESP32: tasks 1–4, one commit per task (no debounce, time-based, state-based, polling), the false triggers counted on the board and a comparison table. STM32: an EXTI interrupt on both edges of PB5 only flags the edge; the loop checks the level 30 ms later and, on the release, toggles one LED for a short press and the board's blue LED for a long one (task 3 and the extra short / long / after-release tasks) ([assignment](00-homework-button-debounce-esp32/README.md#assignment)) |

## Working with the steps

Every ESP32 step is an ordinary PlatformIO project on ESP-IDF, written in C: `platformio.ini`, `src/main.c`, the two
`CMakeLists.txt` the PlatformIO wizard makes for ESP-IDF, and `sdkconfig.defaults`.

- **Build / Upload:** open the step's folder in VS Code (or add it to the workspace) and use the PlatformIO buttons,
  or from the terminal: `pio run -d <step-folder>`.
- **Serial Monitor:** the UART USB-C port, 115200 baud (set in `platformio.ini`).

Every `-stm32` step is an STM32CubeIDE project generated by CubeMX: see its README, "Working with the step".
