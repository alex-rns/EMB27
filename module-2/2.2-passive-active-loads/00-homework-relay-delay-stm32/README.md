# 00 — Homework: relay switching delay on the STM32 (Black Pill)

The STM32 version of the lesson 2.2 required task on the WeAct Black Pill (STM32F411CEU6): a GPIO drives the same
relay module through the same transistor stage, another GPIO reads the relay's dry contact, and a 1 MHz timer measures
the delay. Written in C inside the `USER CODE` blocks of CubeMX's `main.c`. The git history of this folder shows the
work one change per commit.

The assignment, translated in full, is in the ESP32 version's README:
[`00-homework-relay-delay-esp32`](../00-homework-relay-delay-esp32/README.md#assignment) (pull request #10). This
README describes what differs on the STM32.

## How each point is done

| Point | In the code (`Core/Src/main.c`) |
|---|---|
| A GPIO drives the coil through a transistor | PB0 (`RELAY_OUT`, `HAL_GPIO_WritePin`) → 10 kΩ → BC547 base, as on the ESP32 |
| Another GPIO reads the dry contact, `INPUT_PULLUP` | PB1 (`CONTACT_IN`): GPIO input with the internal pull-up, set in CubeMX; the contact connects it to GND |
| `micros()` | TIM2, a 32-bit timer counting at 1 MHz: `__HAL_TIM_GET_COUNTER(&htim2)` gives microseconds (`uint32_t`) |
| `attachInterrupt` | **not used:** the loop polls PB1 with `HAL_GPIO_ReadPin` until it changes (see Notes) |
| Contact bounce | the polling loop stops at the **first** change of PB1, so the bounce edges after it don't touch the time |
| ≥ 10 measurements in Serial | every cycle prints `relay ON: contact closed after … us` and `relay OFF: contact opened after … us` over USART2 |
| Average switch-on / switch-off time | `sum_on`, `sum_off`, `count`: after every measured cycle the program prints the running average |

A cycle is skipped (`no contact change, cycle skipped`) and left out of the average when the contact doesn't start in
the expected state (open before ON, closed before OFF) or doesn't change within 1 s (`CONTACT_TIMEOUT_US`), for
example when the relay has no power.

## What differs from the ESP32 version

| | ESP32 (ESP-IDF) | STM32 (CubeMX + HAL) |
|---|---|---|
| Pins | GPIO 7 out, GPIO 9 in | PB0 out, PB1 in (both 5 V tolerant, `FT`) |
| Time | `esp_timer_get_time()`, `int64_t` | TIM2: prescaler 99 on its 100 MHz clock → 1 MHz, period 0xFFFFFFFF; `uint32_t` |
| Waiting for the contact | pin interrupt on both edges, the ISR keeps the first one | polling in a `while` loop, with a 1 s timeout |
| Serial output | `printf` → UART0 → the board's CH343P | `snprintf` + `HAL_UART_Transmit` → USART2 (PA2) → a USB-TTL adapter (CH340) |
| Skipped cycle | the contact doesn't change within 1 s | the same, plus a contact that is in the wrong state before the command |

## Project

A CubeIDE project generated by CubeMX into this folder; our code lives only in the `USER CODE` blocks of
`Core/Src/main.c`, which a regenerate keeps.

| Pin | CubeMX setting | Used for |
|---|---|---|
| PB0 | GPIO output, push-pull, no pull, low; label `RELAY_OUT` | the transistor's base, through 10 kΩ |
| PB1 | GPIO input, pull-up; label `CONTACT_IN` | the relay's NO contact |
| PA2 / PA3 | USART2, asynchronous, 115200 8N1 | TX to the USB-TTL adapter (RX unused) |
| PA13 / PA14 | SYS: Serial Wire | SWDIO / SWCLK for the ST-Link |
| PH0 / PH1 | RCC: HSE crystal | 25 MHz crystal |

**Clock:** HSE 25 MHz → PLL (M = 12, N = 96, P = 2) → SYSCLK 100 MHz, APB1 50 MHz. APB1's prescaler is not 1, so the
timers on APB1 (TIM2) get twice its clock, 100 MHz; that is why the prescaler is 99 and not 49.
STM32Cube FW_F4 V1.28.3, CubeMX 6.18.1, CubeIDE 2.2.0.

## Wiring

| Part | Connection |
|---|---|
| PB0 | 10 kΩ → BC547 base |
| BC547 emitter | GND |
| BC547 collector | relay module `IN`, plus a 10 kΩ pull-up to +5 V |
| Relay module `VCC` / `GND` | +5 V / GND (a breadboard power module) |
| Relay contact COM | GND |
| Relay contact NO | PB1 (internal pull-up) |
| Black Pill `G` | breadboard GND (shared ground) |
| PA2 | USB-TTL adapter `RXD`; adapter `GND` → `G`; the adapter's VCC stays unconnected |
| SWD header | ST-Link V2: 3.3V, SWDIO, SWCLK, GND; the board runs from the ST-Link |

PB0 high → the transistor conducts → `IN` goes low → the relay turns on. PB1 reads 0 while the contact is closed and 1
while it is open.

Serial: the adapter's port (`/dev/cu.usbserial-*` on macOS), 115200 baud; CubeIDE shows it in a Console of the type
Command Shell Console → Serial Port.

## Notes

- **Why the transistor, though the module has one of its own.** The module's input stage is a PNP with its emitter on
  5 V, switched on by a low `IN`. A 3.3 V high leaves 1.7 V between its emitter and base, so it never turns off. The
  BC547 with the 10 kΩ pull-up to 5 V gives `IN` a full 0 / 5 V swing (found on the ESP32 in lesson 1.7).
- **Polling instead of the interrupt.** EXTI comes later in the course, and the teacher accepted a plain input read
  in a loop for this task. With nothing else to do, the busy-wait costs nothing here, and the first change of PB1 ends
  it, as the ESP32's first-edge ISR does. The ESP32's own polling version (in its history) gave the same times.
- **The prints come after both measurements.** USART2 needs about 87 µs per character at 115200, so a print between
  the two timer reads would add milliseconds to the result.
- **Wrap of the timer.** `now - t0` with `uint32_t` stays right across the counter's wrap (every 71.6 minutes), the
  same rule as `millis()`. The sums are `uint32_t` too: `sum_off`, the larger, grows by ~4150 us a cycle and wraps
  after ~1 million cycles, about 24 days of running at ~2 s a cycle.
- **`%lu` for `uint32_t`.** In arm-none-eabi-gcc `uint32_t` is `unsigned long`; `%u` would give a `-Wformat` warning.
- **No `printf`.** With no OS, `printf` reaches the UART only through a `__io_putchar` function of our own (called
  from `_write` in `syscalls.c`); without it the call is linked as a no-op and nothing appears. The code uses
  `snprintf` into a buffer and `HAL_UART_Transmit` instead, so the path to the pin is visible.

## Checked on the board

Serial output of the average step (dc8b056), after a reset with the relay powered, 10 cycles:

| | 10 measurements, us | Average |
|---|---|---|
| ON | 3296 3290 3292 3293 3297 3299 3301 3303 3310 3305 | **3298 us ≈ 3.3 ms** |
| OFF | 4150 4145 4144 4137 4134 4131 4131 4124 4121 4125 | **4134 us ≈ 4.1 ms** |

The ESP32 version measured 3312 us and 4122 us with the same relay. Over a run ON creeps up and OFF down, on both
boards.

The last commit, with the relay's power switched off for two cycles and back on:

```
relay ON:  contact closed after 3297 us
relay OFF: contact opened after 4132 us
average of 13: ON 3292 us, OFF 4151 us

no contact change, cycle skipped

no contact change, cycle skipped

relay ON:  contact closed after 3306 us
relay OFF: contact opened after 4128 us
average of 14: ON 3293 us, OFF 4149 us
```

Before the start-state check, a power cut during the relay's 1 s on gave `relay OFF: contact opened after 1 us` (the
contact had already opened) and pulled the OFF average from 4153 to 3834 us; the check skips such a cycle.

Build (Debug, `-O0 -g3`): 0 errors, 0 warnings with CubeIDE's flags and with `-Wextra`. `arm-none-eabi-size`: `text`
13308, `data` 92, `bss` 2044 bytes. The formatting code behind `snprintf` is most of the growth: the generated
project alone had `text` 9112, the first step with `snprintf` 12896.

## Working with the step

- **Open:** in CubeIDE, File → Open Projects from File System → this folder (opened in place, not copied into the
  workspace).
- **Build:** Project → Build Project (the hammer).
- **Flash:** Run → Run As → STM32 C/C++ Application, with the ST-Link connected. Launch files (`*.launch`) hold
  absolute paths and are not committed, so the first Run creates one.
- **Change pins or the clock** in `00-homework-relay-delay-stm32.ioc` with CubeMX, then regenerate: everything in
  `main.c` outside the `USER CODE` blocks is rewritten.
