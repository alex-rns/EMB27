# 01 — Homework: Embedded C++ blink on the STM32 (Black Pill)

The STM32 version of the lesson 2.1 homework: the required tasks 1 and 2 on the WeAct Black Pill (STM32F411CEU6),
in C++ on top of a CubeMX project. The optional tasks 3 (loop timing) and 4 (button on an interrupt) are not done in
this version. The git history of this folder shows the work one change per commit.

The assignment, translated in full, is in the ESP32 version's README:
[`01-homework-blink-esp32`](../01-homework-blink-esp32/README.md#assignment) (pull request #6). This README
describes what differs on the STM32.

## How each point is done

| Point | In the code |
|---|---|
| `enum class` for the LED state | `enum class LedState { On, Off }` in `Core/Inc/led.h` |
| `constexpr` pin and interval | `Config::kLedPin = GPIO_PIN_13` (`uint16_t`), `Config::kBlinkIntervalMs = 1000` in `Core/Inc/config.h` |
| Minimal globals | `Led led` (used by both `app_setup()` and `app_loop()`); the loop's state lives in `static` locals inside `app_loop()` |
| No `delay()` | `app_loop()` toggles the LED when `nowMs - lastToggleMs >= Config::kBlinkIntervalMs`, with `nowMs = HAL_GetTick()`, and returns at once otherwise |
| `Led` class | `init()` sets the starting state (off), `set(LedState)` writes the pin through `HAL_GPIO_WritePin()` |
| Config struct, no magic numbers | `struct Config`: `static constexpr` pin and interval, and the port as `static GPIO_TypeDef* ledPort()` (see Notes) |
| No dynamic memory, no STL | no `new` or containers in our code |

## Project

A CubeIDE project generated by CubeMX into this folder, then converted to C++ in CubeIDE (right-click on the project
→ Convert to C++). CubeMX keeps generating C: `main.c` stays C and only calls our code from its `USER CODE` blocks,
which a regenerate keeps:

| File | What it holds |
|---|---|
| `Core/Src/main.c` | `#include "app.h"`; `app_setup()` after `MX_GPIO_Init()`; `app_loop()` inside `while (1)` |
| `Core/Inc/app.h` | the two functions' declarations inside `extern "C"` (guarded by `#ifdef __cplusplus`) |
| `Core/Src/app.cpp` | `Led led`, `app_setup()`, `app_loop()` |
| `Core/Inc/config.h` | `struct Config` |
| `Core/Inc/led.h` | `enum class LedState`, `class Led` |

| Pin | CubeMX setting | Used for |
|---|---|---|
| PC13 | GPIO output, push-pull, no pull, low speed | the onboard blue LED, lit on LOW |
| PA13 / PA14 | SYS: Serial Wire | SWDIO / SWCLK for the ST-Link |
| PH0 / PH1 | RCC: HSE crystal | 25 MHz crystal |

**Clock:** HSE 25 MHz → PLL (M = 12, N = 96, P = 2) → SYSCLK 100 MHz, AHB 100 MHz, APB1 50 MHz, APB2 100 MHz.
STM32Cube FW_F4 V1.28.3, CubeMX 6.18.1, CubeIDE 2.2.0.

**Wiring:** only the ST-Link, to the board's SWD header, as in
[lesson 1.8](../../../module-1/1.8-stm32-blink/00-lecture-blink/README.md). The LED is on the board.

## Notes

- **`extern "C"` in `app.h`:** C++ encodes a function's parameter types into its symbol name; `app_setup()` compiled
  as plain C++ would be `_Z9app_setupv`, and `main.c` (C) would look for `app_setup` and fail to link with
  `undefined reference`. Inside `extern "C"` the symbol stays `app_setup` (`nm` on `app.o`: `T app_setup`).
- **The pin is a mask, not a number.** `GPIO_PIN_13` is `((uint16_t)0x2000)`, bit 13 of the port. In a `uint8_t` it
  becomes 0 (GCC warns: `-Woverflow`, "changes value from '8192' to '0'", but the build succeeds); `HAL_GPIO_WritePin`
  then writes 0 to `BSRR`, which changes no pin. HAL's own check (`assert_param`) is off, since `USE_FULL_ASSERT` is
  commented out in `stm32f4xx_hal_conf.h`, so nothing reports it, and the LED stays lit. A pin *number* such as `7`
  compiles silently and selects PC0–PC2 (mask `0b111`), which the Black Pill doesn't break out.
- **The port can't be `constexpr`.** `GPIOC` is `((GPIO_TypeDef *) GPIOC_BASE)`, an integer cast to a pointer to
  the port's registers. In C++ that is a `reinterpret_cast`, which a constant expression may not contain:
  `static constexpr GPIO_TypeDef* kLedPort = GPIOC;` fails with "`reinterpret_cast<GPIO_TypeDef*>(1073874944)` is not
  a constant expression". `Config::ledPort()` returns `GPIOC` instead. A `static GPIO_TypeDef* const` member works
  too, but C++14 (CubeIDE's `-std=gnu++14`) needs its value in a separate definition outside the struct, and the
  `const` must follow the `*`: a `const GPIO_TypeDef*` (pointer to read-only registers) can't be passed to
  `HAL_GPIO_WritePin`.
- **The LED is lit by LOW.** Its anode sits on 3.3 V through 1.5 kΩ, so `set(LedState::On)` writes `GPIO_PIN_RESET`.
  `MX_GPIO_Init()` writes PC13 low before switching it to output, so the LED is on from reset until `led.init()`
  turns it off.
- **Pin setup lives in CubeMX.** The pin mode comes from the `.ioc` through the generated `MX_GPIO_Init()`, so
  `Led::init()` only sets the starting state; on the ESP32 it calls `pinMode()`.
- **`HAL_GetTick()`** counts milliseconds from the SysTick interrupt (1 ms), like `millis()`. `uint32_t` wraps after
  49.7 days; `now - last >= interval` keeps working across the wrap.
- **A new `.cpp` needs a CubeIDE build first.** CubeIDE writes the makefiles in `Debug/` from the files it sees; a
  build run from the terminal (`make -C Debug`) with makefiles older than `app.cpp` doesn't compile it and fails to
  link with `undefined reference to 'app_setup'`. Headers need nothing: `Core/Inc` is already on the include path.

## Checked on the board

- After every commit: built, flashed through the ST-Link, and the LED on PC13 blinks once a second (1 s on, 1 s off).
- Build (Debug, `-O0 -g3`): 0 errors, 0 warnings. `arm-none-eabi-size`: `text` 5960, `data` 16, `bss` 1576 bytes.
  The RAM figure includes `._user_heap_stack`, 1536 bytes reserved for the heap and the stack; our variables are
  `led` (1 byte, `.bss`), `lastToggleMs` (4, `.bss`) and `ledState` (4, `.data`: it starts at `Off` = 1, not 0).
- The constants cost nothing: `nm` finds no `Config::kLedPin` or `Config::kBlinkIntervalMs`, the values sit in the
  instructions. `Config::ledPort()` is a 20-byte function at `-O0`; at `-O2` it is inlined (checked on a test file).
- CubeIDE's C++ flags: `-std=gnu++14 -fno-exceptions -fno-rtti -fno-use-cxa-atexit -Wall` (no `-Wextra`).
  `app.cpp` and `main.c` compiled by hand with `-Wall -Wextra` give no warnings either.

## Working with the step

- **Open:** in CubeIDE, File → Open Projects from File System → this folder (opened in place, not copied into the
  workspace). A project with the same name can't be open in the same workspace twice.
- **Build:** Project → Build Project (the hammer).
- **Flash:** Run → Run As → STM32 C/C++ Application, with the ST-Link connected. Launch files (`*.launch`) hold
  absolute paths and are not committed, so the first Run creates one.
- **Change pins or the clock** in `01-homework-blink-stm32.ioc` with CubeMX, then regenerate: everything in `main.c`
  outside the `USER CODE` blocks is rewritten.
